# 2단계 — 사용 매뉴얼 (처음 쓰는 사람용)

대상: 팜코지엘에스 부킹 업무 담당자. 엑셀만 쓸 수 있으면 됩니다.
프로그램 설치, 로그인, 인터넷 연결 모두 필요 없습니다.

---

## 0. 시작하기 (1분)

여는 방법이 두 가지입니다. **둘 다 같은 도구**이고, 하는 일도 똑같습니다.

### 방법 A — 홈페이지 (다른 사람에게 알려줄 때)

1. 브라우저에서 주소를 엽니다.
   ```
   https://inu-sudo.github.io/farmkogls-console/
   ```
2. **PIN 4자리**를 누릅니다. (번호는 담당자에게 확인하세요 — 이 문서에는 적지 않습니다)
3. 끝입니다.

설치할 것도, 파일을 받을 것도 없습니다. 회사 PC가 꺼져 있어도,
휴대폰에서도 열립니다.

### 방법 B — 파일 (내 PC에서 늘 쓸 때)

1. 바탕화면 `claude` 폴더의 **`Farmkogls_Booking_Console.html`**을 더블클릭합니다.
2. 브라우저가 열리면 끝입니다.

인터넷이 끊겨도 되고, PIN도 없습니다. 파일 하나(239KB)라서
**메일에 첨부해서 보내면 그게 곧 배포**입니다.

### 어느 쪽을 쓰나

| | 홈페이지 | 파일 |
|---|---|---|
| 알려주기 | 주소 + PIN만 | 파일을 보내야 함 |
| 인터넷 | 처음 열 때만 필요 | 전혀 불필요 |
| 갱신 | 항상 최신 | 새 파일을 다시 받아야 함 |
| 엑셀 내려받기 | 됨 | 됨 |

> **참고 — Artifact 판은 예외입니다.** claude.ai 안에서 열리는 판은
> 보안 제약 때문에 **엑셀 파일을 내려받을 수 없습니다.** 화면으로 보는 건
> 다 되지만, 실제 `.xlsx`가 필요하면 위 홈페이지나 파일을 쓰세요.
> (Artifact 판 화면에도 도구 파일을 내려받는 버튼이 있습니다.)

**필요 조건**
- Microsoft Edge, Chrome, 또는 Firefox 113 이상. (Internet Explorer 불가)
- 브라우저가 맞지 않으면 화면에 그렇게 안내가 뜹니다. 조용히 실패하지 않습니다.

**보안 안심 사항**
- 드롭한 엑셀은 **내 브라우저 안에서만** 열립니다. 서버로 올라가지 않습니다.
  홈페이지로 열어도 마찬가지입니다 — **홈페이지는 도구를 배달할 뿐**,
  파일 내용은 어디로도 전송되지 않습니다.
- 파일(방법 B)은 인터넷을 끊어도 똑같이 동작합니다.

> 홈페이지에는 **부킹 자료가 들어 있지 않습니다.** 빈 도구만 올라가 있고,
> 자료는 각자 파일을 넣는 순간부터 그 사람 브라우저에만 쌓입니다.

### 문서는 관리자 PIN이 따로 있습니다

이 문서들(사용설명서·설계 지침서·기술 참고·배포 안내)은
**도구와 다른 관리자 PIN**으로 열립니다.

문서 본문은 **그 PIN으로 암호화되어 있습니다.** 번호를 넣기 전에는
페이지 안에 글자가 없습니다 — 화면에 안 보이는 게 아니라 아예 없습니다.

## 2. 주간 업무 루틴 ⭐ — 「파일 갱신」이 본체입니다

**목적: 에이전트가 보낸 예보를 통합 등록부에 반영해서, 갱신된 등록부를 돌려받는 것.**

| 순서 | 할 일 |
|---|---|
| 1 | 파일을 연다 (`파일 갱신` 탭이 처음부터 열려 있습니다) |
| 2 | **`학습.xlsx`와 `FES AGENCY BOOKING FORECAST 학습.xlsx`를 함께** 끌어다 놓는다 |
| 3 | 어느 쪽이 입력이고 대상인지 자동 판별됩니다 — 두 칸이 초록색이 되는지 확인 |
| 4 | **`③ 등록부에 반영하기`** 클릭 |
| 5 | 화면에 나온 **변경 내역**을 확인 (무엇이 새로 들어가고 무엇이 바뀌는지) |
| 6 | **`⬇ 갱신된 파일 내려받기`** 클릭 → 회신 |

**원본 파일은 건드리지 않습니다.** `..._updated_20260725_1432.xlsx` 같은 새 사본이 나옵니다.

### 무엇이 보존되나

대상 파일을 새로 만드는 게 아니라 **필요한 칸만 고칩니다.** 그래서 그대로 남습니다:

- 모든 **수식** (`=WEEKNUM(...)`, TEU 계산식, Lumpsum 계산식)
- 셀 서식, 배경색, 테두리, 숫자 서식
- 병합 셀, 자동 필터, 조건부 서식
- **그림, 메모, 인쇄 설정**, 다른 시트(`Schedule`)

새로 추가되는 행은 **바로 위 데이터 행의 서식과 수식을 물려받습니다.**
행이 추가되면 아래쪽 `** CANCEL LIST` 블록이 자동으로 밀려나고, 그 안의 수식과
메모 위치도 함께 조정됩니다.

### 실제 예 (제공해주신 파일로 검증한 결과)

```
학습.xlsx  16행  →  FES BK FCST
  신규 삽입 11건 (375행부터)   기존 갱신 5건   변화 없음 0건
  → CANCEL LIST 378행 → 389행으로 이동
  → 활성구역 TEU 합계 2,460 → 2,576 (증가 116 = 신규 11행 합계와 일치)
```

갱신된 5건의 내용:

| 행 | 무엇이 바뀌나 |
|---|---|
| 327 | B열에 화주명 추가 (예보에는 있고 등록부에는 비어 있던 값) |
| 352 | B열에 화주명 추가 (위와 같음) |
| 344 · 373 | **ETD `2026-07-27` → `2026-07-31`** (등록부가 예보보다 뒤처져 있었음) |
| 344 · 373 · 374 | **T/S 항구 오타 `MPYKG(N)` → `MYPKG(N)`** |

### 반드시 직접 채워야 하는 것

도구가 채우지 않고 비워두는 칸이 있습니다. **학습.xlsx에 그 정보가 없기 때문입니다.**

| 비워두는 칸 | 이유 |
|---|---|
| **T/S 행의 `I`(2nd Leg Vessel) · `J`(ETD) · `N`(2nd SVC)** | 환적 연결 배는 예보에 없습니다. 담당자가 정하는 정보입니다 |
| `Z` (VGM 중량) | 학습.xlsx에 비어 있으면 비워둡니다 (추정하지 않음) |
| `AB` (Rate/Box) | 위와 같음 |
| `C` (Customer) | 지금 관행대로 비워둡니다 (화주명은 `B` Remark에 들어갑니다) |

화면 아래 **「T/S 행 — 2nd Leg를 직접 채워야 합니다」** 표에 해당 행이 전부 나옵니다.
그 목록만 보고 엑셀에서 채우면 됩니다.

### 같은 파일을 또 넣어도 안전합니다

같은 학습.xlsx를 갱신된 파일에 다시 반영해도 **신규 0 · 갱신 0 · 변화없음 16**이 나옵니다.
실수로 두 번 돌려도 행이 중복되지 않습니다.

## 2-1. 분석 화면 (부가 기능)

파일을 넣으면 갱신 작업과 별개로 분석 화면도 채워집니다. 필요할 때만 보세요.

| 순서 | 할 일 | 어디서 |
|---|---|---|
| 1 | 받은 엑셀을 한꺼번에 끌어다 놓는다 (BK SHEET, ROB, DF 계산기까지) | 드롭 영역 |
| 2 | **Changes** 탭에서 지난주와 무엇이 달라졌는지 확인 | Changes |
| 3 | **Voyages vs BSA** 탭에서 빨간 항차를 확인 (= 초과 선복 비용) | Voyages |
| 4 | **`⬇ Export Excel`** 로 14시트 통합 리포트를 받는다 | 하단 |

> `⬇ Export Excel`은 **새 통합 리포트**를 만드는 것이고,
> `파일 갱신`은 **기존 등록부를 고쳐서** 돌려주는 것입니다. 용도가 다릅니다.

여러 번 같은 파일을 넣어도 **아무 일도 일어나지 않습니다**(`동일 1,182건`).
잘못 넣었을까 걱정하지 말고 그냥 다시 넣으세요.

파일을 넣는 **순서는 결과에 영향을 주지 않습니다.** 6개를 어떤 순서로 넣어도
같은 결과가 나오도록 만들어 두었습니다.

## 3. 어떤 파일을 넣을 수 있나

한 번에 몇 개든 섞어서 넣어도 됩니다. 도구가 시트별로 알아서 판별합니다.

| 넣을 수 있는 것 | 도구가 읽는 내용 |
|---|---|
| 에이전트 주간 예보 (`FES CSC/NWX/CCS/SKS BK FCST`) | 부킹, `SVC NAME` 셀에서 서비스 |
| 통합 등록부 (`FES BK FCST`) | 부킹 + 2구간/환적, 하단 `** CANCEL LIST`까지 |
| 항차별 BK SHEET (`… 마감`) | 부킹, 선명/항차, **BSA(TEU·톤)**, DF 단가, 서류·화물 마감일, Win-Sabis 코드, 하단 `Cancel 정리` |
| `Schedule` / `SCHEDULE` | 서비스별 기항 순서와 항구별 ETD |
| `<SVC> BSA` | 항차별 배정량, 선박 대체(`A => B`) 표기 |
| DF 계산기 (`GFS_`, `BTL_`, `XPR_`) | 단가, 약정 물량·중량, 할증 |
| 항차별 ROB | BSA 상한값 (적재계획 자체는 도구가 다시 계산) |
| `.json` 프로젝트 파일 | 저장해둔 등록부 전체 복원 |

**판별하지 못한 시트는 버리지 않고 알려줍니다.**
`Changes` 탭 맨 위 `Last upload`에 "이 시트는 인식하지 못했습니다"로 나옵니다.
(예: `7월 RCL 모선`, `서인도스케줄`, `위험물 CHECKLIST GFS` 같은 자유형식 시트)

## 4. 탭별 사용법

### 4-1. Overview — 아침에 30초만 볼 화면

- **상단 4개 타일** — 활성 부킹 수 / 활성 TEU / VGM 중량 / **BSA 초과 항차 수**
  네 번째 타일에 "초과 선복 몇 TEU"가 같이 나옵니다. 바로 돈입니다.
- **주차별 TEU 누적 막대** — 서비스별 색으로 쌓여 있습니다.
  막대에 마우스를 올리면 `WK 30 · CCS · 123.0 TEU`처럼 뜹니다.
- **Service mix / Top lanes / Booking parties** — 어디에 물량이 몰렸는지.
- **Checks and exceptions** — 여기가 핵심입니다. 아래 3종류가 섞여 나옵니다.
  - `OVER` — BSA(또는 중량) 초과 항차
  - `WARN` — 파일 간 값 불일치, 서비스 헤더 오타 정정, TEU 재계산 불일치
  - `INFO` — 서비스/ETD 누락, 모르는 항구 코드
- **Container mix** — 20'DV, 40'HC, Void 등 실제 박스 구성.

### 4-2. Voyages vs BSA — 돈이 보이는 화면

항차 한 줄씩. **열 제목을 클릭하면 정렬**됩니다.

| 열 | 뜻 |
|---|---|
| `Booked TEU` | 부킹 수량 단순 합계 |
| **`Peak TEU`** | **최대 선상 잔량 = 실제 필요한 선복** |
| `BSA` | 우리 배정량 |
| `Remain` | 남은 선복. **음수(빨강)면 초과** |
| `Utilisation` | 이용률 막대. 85% 넘으면 주황, 100% 넘으면 빨강 |
| `Peak t / BSA t / Remain t` | 중량 기준 같은 것 |
| `DF cost / Selling / Margin` | BK SHEET에 DF 원가가 있던 항차만 표시 |

> **`Booked TEU`와 `Peak TEU`를 혼동하지 마세요.**
> 부산에서 실어 첸나이에서 내린 박스는 그 뒤 구간 선복을 쓰지 않습니다.
> 선사와 정산할 근거는 `Peak TEU`입니다.

### 4-3. ROB load plan — 구간별 상세

항차를 클릭해 펼치면 기항지 순서대로:

```
#  항구    ETD     적재  20'  40'  DG  OOG   양하   선상   잔여   중량
1  CNTAO   04/25    37    0   18            
2  KRPUS   04/27    30    ...              −30     37     42    416.7
3  CNSHA   05/01     5                              42     37    494.3
...
```

- `선상(On-board)`이 그 구간에서 실제로 쓰는 선복입니다.
- `잔여(Remain)`가 음수면 그 구간이 초과입니다.
- **어느 구간에서 터졌는지**를 보고 어떤 부킹을 옮길지 판단합니다.

### 4-4. Bookings — 원장 조회

- 필터 + 검색으로 좁히고, 열 제목 클릭으로 정렬.
- 화면에는 **최대 600행**만 그립니다(빠르게 유지하려고). 전체는 엑셀로 받으세요.
- 맨 아래 합계 줄은 **지금 화면에 보이는 행들의 합**입니다.
- `St` 열의 `CXL`은 취소 건.
- `SVC` 열의 **⚑ 표시** = 원본 시트 헤더와 스케줄이 달라 스케줄을 따랐다는 뜻.
  마우스를 올리면 원본에 뭐라고 적혀 있었는지 나옵니다.

### 4-5. Changes — 지난주와 뭐가 달라졌나

위에서 아래로 4개 구역:

1. **Last upload** — 방금 넣은 파일별로 몇 건 읽었고 어떤 시트를 못 읽었는지.
2. **Source disagreements** — ⭐ **가장 중요**.
   같은 부킹인데 파일마다 값이 다른 경우를 **양쪽 출처(파일 › 시트)와 함께**
   나열합니다. 어느 쪽을 채택했는지도 표시됩니다. 손으로 확인해야 할 목록입니다.
3. **Merge history** — 배치별 `신규/변경/동일/취소/중복접힘/누적` 이력.
4. **Row-level changes** — 어느 B/L의 어느 항목이 무엇에서 무엇으로 바뀌었는지.

### 4-6. Reference — 기준 정보

서비스별 기항 순서, 데이터에서 학습한 **선박→서비스** 대응표,
읽어들인 DF 계약 목록, 항구 코드표.

## 7. 백업과 기기 이동

| 버튼 | 언제 쓰나 |
|---|---|
| `Save project file` | **정기적으로**, 그리고 다른 PC로 옮길 때. `.json` 하나로 등록부 전체가 저장됩니다 |
| `.json`을 다시 드롭 | 저장한 등록부를 복원 |
| `Clear register` | 새 시즌 시작 등 처음부터 다시 할 때. **되돌릴 수 없습니다** (확인창이 뜹니다) |

등록부는 브라우저에 자동 저장되어 창을 닫아도 남습니다.
다만 브라우저 저장 공간은 약 5MB(부킹 4,000~5,000건)가 한계이고,
**한계에 가까워지면 미리 경고**합니다. 그때는 프로젝트 파일로 저장하고
지난 시즌을 정리하세요.

### ⚠️ 등록부는 사람마다 따로입니다

**홈페이지로 열든 파일로 열든, 등록부는 그 브라우저에만 쌓입니다.**
공유 서버가 없기 때문입니다.

- 같은 홈페이지를 두 사람이 열어도 **서로의 등록부는 보이지 않습니다.**
- 회사 PC에서 넣은 파일은 집 PC에서 안 보입니다.
- 브라우저 기록을 지우면 등록부도 같이 지워집니다.

**여럿이 같은 등록부를 봐야 한다면** `Save project file`로 `.json`을 만들어
공유 폴더나 메일로 넘기고, 받은 쪽이 그걸 드롭하면 됩니다.
이게 현재 유일한 공유 방법입니다. (실시간 공유가 필요하면 별도 작업입니다 —
서버가 생기고, 그러면 보안 검토가 따라옵니다.)

## 8. 이런 상황이면 (FAQ)

**Q. 파일을 넣었는데 "인식된 시트 없음"이 뜬다**
→ 헤더 행에 `B/L NO`와 컨테이너 규격 열(`20'DV` 등)이 있어야 부킹 시트로 봅니다.
자유형식 메모 시트는 원래 대상이 아닙니다. `Changes › Last upload`에서
어떤 시트를 건너뛰었는지 확인하세요.

**Q. 취소한 부킹이 계속 살아 있다**
→ 취소는 **한 번 취소되면 유지**됩니다(어느 파일에서든 취소로 나오면 취소).
나중에 올린 파일이 취소 목록을 지워버리는 사고를 막기 위한 설계입니다.
되살려야 하면 알려주세요(현재는 `Clear` 후 재적재해야 합니다).

**Q. `Peak TEU`가 `Booked TEU`보다 작다**
→ 정상입니다. 중간 기항지에서 내린 박스만큼 선복이 풀린 것입니다.

**Q. 이용률이 100%를 넘는다**
→ 실제로 BSA를 초과한 것입니다. 초과 선복 비용이 발생합니다.
지금 데이터에서는 27개 항차, 476 TEU가 초과였습니다.

**Q. 서비스에 ⚑ 표시가 붙었다**
→ 원본 시트의 `SVC Name`과 그 항차의 스케줄이 다릅니다.
한 선박이 한 항차에 두 루프를 돌 수는 없으므로 스케줄을 따랐습니다.
`Overview › Checks`에 어느 시트를 고쳐야 하는지 나옵니다.

**Q. 값이 이상한데 어느 파일에서 왔는지 알고 싶다**
→ `Bookings` 탭 맨 오른쪽 `Source` 열(시트명, 마우스 올리면 파일명),
그리고 엑셀 `MASTER BK FCST`의 `Source File / Source Sheet / Src Row` 열.

**Q. 같은 부킹이 두 파일에 있고 값이 다르면 어느 쪽을 쓰나**
→ ① 항차별 BK SHEET(마감) > 통합 등록부·에이전트 예보,
② 같은 등급이면 **더 최근에 저장된 파일**,
③ 그래도 같으면 파일명·시트명 순서(항상 같은 결과가 나오도록).
어느 쪽을 버렸는지는 `Changes › Source disagreements`에 전부 남습니다.

## 9. 알아둘 한계

- **항차 번호는 선명+항차번호로만 식별**합니다. 연도 구분이 없으므로
  25년 파일과 26년 파일을 같이 넣으면 같은 항차번호가 합쳐집니다.
  **시즌별로 등록부를 나누어 쓰세요.**
- **B/L이 없는 행**(`MT`, `FULL`, `T.B.N`, 공컨 회수)은 문서번호가 없어
  항차·구간·거래처·박스구성·비고와 **시트 내 등장 순서**로 식별합니다.
  그 행의 비고를 고치면 새 행처럼 보이고, 같은 모양 행 사이에 한 줄을
  끼워 넣으면 뒤 행들의 식별이 밀립니다.
- **마진은 부분적**입니다. 항차 BK SHEET에 DF 원가가 있는 항차만 계산합니다.
  초과 선복 단가와 할증은 `DF CONTRACTS`에 참고용으로만 실려 있습니다.
- **`.xls`(구형)는 지원하지 않습니다.** `.xlsx`만 됩니다.
- 운임 파일 6종은 아직 연결되지 않았습니다(판매운임 자동 적용은 다음 단계).

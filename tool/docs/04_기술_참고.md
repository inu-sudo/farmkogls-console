## 1. 설계 전제 3가지

### 1-1. 의존성 0
`npm install` 하나 없습니다. 이유:

- 이 PC에는 Node도 Python도 없었습니다(PATH의 `python.exe`는 Microsoft Store
  스텁이라 실행되지 않음). 담당자가 바뀌어도 동작해야 합니다.
- 데이터가 상업 기밀입니다. 외부로 나가는 요청이 **하나도 없어야** 합니다.
- 5년 뒤에도 열려야 합니다. CDN이 죽으면 도구가 죽는 구조는 피했습니다.

그래서 `.xlsx` 읽기/쓰기를 직접 구현했습니다.

- **읽기** — 브라우저 내장 `DecompressionStream('deflate-raw')`로 ZIP 해제
  (SheetJS 약 900KB를 넣지 않아도 됨)
- **쓰기** — ZIP을 **STORE(무압축)** 방식으로 생성 + CRC32 직접 계산.
  엑셀은 무압축 xlsx도 문제없이 엽니다.

### 1-2. 원본을 덮어쓰지 않고 파생시킨다
소스에서 읽은 값(`svc1`)은 절대 수정하지 않고, 보정값은 별도 필드(`svcEff`)에
둡니다. 한 번 원본을 덮어썼다가 **무한 진동 버그**를 만들었습니다(§5-8 참조).

### 1-3. 조용히 해결하지 않는다
값이 충돌하면 규칙대로 하나를 고르되, **버린 값과 양쪽 출처를 반드시 기록**합니다
(`Changes › Source disagreements`, `DATA QUALITY` 시트).
통합 도구가 사람 모르게 값을 고르기 시작하면 신뢰를 잃습니다.

## 2. 구조와 데이터 흐름

```
 엑셀 파일 (ArrayBuffer)
        │
   zip.js          ZIP 해제 / 생성          7.6 KB
        │
   xlsx-read.js    시트 → 2차원 셀 배열      9.0 KB
        │          (공유문자열·날짜·병합셀)
        ├──────────────────────────────────────────────┐
        │                                              │
        │                              [파일 갱신 경로]  │
        │                        xlsx-edit.js  기존 파일 정밀 편집
        │                              │       행 삽입·참조 이동·부분 저장
        │                        propagate.js  학습→FES BK FCST 매핑
        │                              │
        │                              └─▶ 갱신된 대상 파일 (새 사본)
        ▼
   parse.js        레이아웃 판별 →          31.5 KB
        │          정규 레코드              ← 가장 자주 손댈 파일
        │  ↕ normalize.js  항구·선박·거래처·TEU·주차   14.9 KB
        ▼
   merge.js        누적 등록부              21.0 KB
        │          키·그룹병합·변경이력      ← 가장 어려운 파일
        ▼
   aggregate.js    집계 + ROB 재계산        15.0 KB
        │
        ├──▶ ui.js       화면              43.7 KB
        └──▶ export.js   14시트 엑셀        16.7 KB
                  │
             xlsx-write.js  서식 있는 xlsx  12.2 KB
```

로드 순서가 곧 의존 순서입니다(`index.html` 하단 참조).
전역 객체 `FZip` `FXlsxRead` `FXlsxWrite` `FNorm` `FParse` `FMerge` `FAgg`
`FExport` `FApp`로 노출됩니다. 모듈 시스템을 쓰지 않은 이유는
`file://`에서 ES module이 CORS로 막히기 때문입니다.

## 3. 정규 데이터 모델

모든 레이아웃이 이 한 가지 모양으로 수렴합니다. 여기가 계약(contract)입니다.

```js
{
  // 출처 (추적용)
  srcFile, srcSheet, srcRow, srcKind, srcMtime, srcRank,
  key,            // 병합 식별자
  status,         // 'active' | 'cancel'
  occ,            // B/L 없는 행의 시트 내 등장 순번

  // 당사자
  remark, customer, bkParty, partySvc, blNo,

  // 1구간 / 2구간
  leg1Vessel, leg1Voy, leg1Etd, wk,
  leg2Vessel, leg2Voy, leg2Etd, wk2,
  dirTs,          // 'DIR' | 'TS'
  svc1, svc2,     // 원본이 말한 서비스
  svcEff,         // ← 실제 사용할 서비스 (파생)
  voyKey, voyKey2,

  // 구간
  pol, ts, pod, fpod, lane,

  // 수량 (이 7개가 원천, 나머지는 계산)
  c20dv, c20mt, c40hc, c40mt, c20fr, c40fr, cvoid,

  // 파생
  teu, boxes, vgmWt, wtPerTeu, tare, emptyRepo,

  // 상업
  item, ratePerBox, lumpsum,

  // BK SHEET 전용
  special, specialApproval, salesRep, billingNote,
  pickupTerminal, pickupDate, bkDate, cancelDate,

  // 이력
  firstSeen, lastSeen, history[], mergedFrom[]
}
```

**원칙**: `c20dv…cvoid` 7개만 원천 데이터. `teu`는 항상 이 7개에서 재계산합니다
(`FNorm.computeTeu`). 원본 시트의 TEU 값은 `teuSheet`에 따로 보관해두고
다르면 경고를 냅니다 — 실제로 `FES BK FCST`의 VGM 수식이 깨져 있었습니다.

## 4. 핵심 알고리즘 3개

### 4-1. 레이아웃 판별 (`parse.js`)

시트 이름에 의존하지 않습니다(`마감`, `(0726)`, 오타 등으로 이름이 제각각).
**헤더 행을 찾아 그 내용으로 판별**합니다.

```
1~40행을 훑어 각 행을 점수화
  헤더 텍스트를 정규 필드명으로 매핑 (H_EXACT 사전 + 느슨한 패턴)
  조건: 매칭 6개 이상 + 컨테이너 열 2개 이상 + B/L 열 존재
  → 최고점 행이 헤더

판별:
  '1st Leg Vessel' 있음                    → masterForecast
  'Pick Up' / 'Cancel Date' / 'Shipper' 등 → bkSheet
  'Vessel' + 'Voy' 분리                    → agencyForecast
  'VSL/VOY' + 'WK' 반복                    → schedule
  'NORTHBOUND/SOUTHBOUND'                  → bsa
  'DF Contract' + 'RATE :'                 → dfContract
  'TOTAL(Incl. ROB)' / 'OOG(Void)'         → rob
```

열 위치가 파일마다 밀려도 견딥니다. **새 양식 대응은 대부분
`H_EXACT`에 헤더 문자열 한 줄 추가로 끝납니다.**

데이터 행 종료 조건이 의외로 까다롭습니다. 데이터 구역 안에
소계·합계·`Cancel 정리`·헤더 재출력이 섞여 있습니다(`TOTALS_HINT_RE`,
`CANCEL_SECTION_RE`).

### 4-2. 그룹 병합 (`merge.js`)

같은 부킹이 최대 3곳에 존재합니다. **2개씩 순차로 합치면 순서 의존이
생깁니다**(§5-7). 그래서 전량을 모아 한 번에 해결합니다.

```js
// 1) 키로 전부 모은다
groups: key → [copy1, copy2, copy3]

// 2) 신뢰도 순으로 정렬 (완전 결정적)
byPrecedence =
  레이아웃 등급 내림차순            // bkSheet 3 > master/agency 2 > 기타 1
  → 파일 수정시각 내림차순          // 같으면 최근 저장분
  → 파일명 → 시트명 → 행번호        // 그래도 같으면 이름순

// 3) 필드별로 "값을 가진 가장 좋은 사본"에서 가져온다
for (필드 of 텍스트+숫자) if (lead[필드] 비어있음) 뒤에서 첫 유효값

// 4) 박스 수량은 세트로 이동 (7개를 쪼개면 TEU가 깨짐)
// 5) 하나라도 cancel이면 cancel
// 6) MATERIAL 필드가 서로 다르면 conflicts[]에 기록
```

**키 설계**가 이 파일의 진짜 어려운 부분입니다.

```js
B/L 있음  → 'B|' + 정규화B/L + '|' + 선명|항차 + '|' + POD
B/L 없음  → 'X|' + (항차|구간|거래처|박스구성|비고해시) + '|#' + 등장순번
```

`MT` / `FULL` / `T.B.N` 같은 자리표시자는 문서번호가 없습니다.
**등장 순번을 키에 넣은 이유**: 같은 시트에 똑같이 생긴 공컨 회수 3줄이
실제로는 별개 부킹입니다. 순번이 없으면 1줄로 뭉개져 물량이 사라집니다
(실제로 3건 7 TEU가 사라지고 있었습니다). 반면 순번을 시트별로만 매기므로,
같은 줄이 다른 파일에 또 나오면 양쪽 `#1`이라 정상 병합됩니다.

### 4-3. ROB 재계산 (`aggregate.js`)

수작업 ROB 시트를 읽는 대신 **부킹에서 다시 만듭니다.**

```js
rotation = 그 항차의 스케줄 기항순서 (없으면 서비스 기본 순서)

// 각 부킹을 정확히 한 번만 적재
for (부킹) loadIdx[부킹] = rotation에서 POL이 처음 나오는 위치

// 기항지 순서대로
for (i, 기항지 of rotation) {
  적재 = loadIdx === i 인 부킹들
  양하 = 하선항 === 기항지 && loadIdx < i && 아직 안 내린 부킹들
  선상 += 적재 − 양하
}
선복소요 = max(선상)          // ← 합계가 아니라 최대값
잔여     = BSA − 선복소요
```

**`loadIdx`가 핵심**입니다. CCS·NWX 루프는 청도와 부산을 **두 번** 기항합니다.
항구 이름만으로 매칭하면 같은 화물을 두 번 싣습니다(§5-3).

## 5. 실제로 만난 버그와 교훈 ⭐

이 절이 이 문서의 핵심입니다. 전부 실제 발생했고, 전부 **조용히 틀린 답**을
내놓던 종류입니다.

### 5-1. 병합셀이 자기 라벨을 되돌려줌
- **증상**: 존재하지 않는 서비스 `SVCNAME`이 2,834 TEU를 차지.
- **원인**: `sh.get()`이 병합 영역을 해석해준다 → `A10:B11`이 병합된
  `"SVC Name :"` 라벨에서 오른쪽 B10을 읽으면 **라벨 자신**이 돌아옴.
  `canonSvc("SVC Name :")` → `"SVCNAME"`.
- **수정**: 라벨과 텍스트가 같은 셀은 건너뛴다(`valueRightOf`).
- **교훈**: 병합셀을 해석해주는 편의 기능이 "라벨 오른쪽 값 읽기"와 충돌한다.

### 5-2. 합계 행이 부킹으로 들어옴
- **증상** : `한국 선적 합계 → 한국 선적 합계` 라는 유령 구간 287 TEU.
- **원인**: 합계 행이 데이터 구역 **안**에 있고, 종료 판정이 영어 키워드만 봤음.
- **수정**: `합계|소계|GRAND TOTAL|ACCOUNT NO|…` 로 확장.
- **교훈**: 한국어 업무 파일은 요약 행이 데이터 중간에 끼어 있다. 영어 키워드만
  보면 반드시 새어 들어온다.

### 5-3. 순환 항로에서 화물을 두 번 실음
- **증상**: `KMTC JEBEL ALI 2602W` 최대 선상 75 TEU (실제 42).
- **원인**: 적재를 항구 이름으로 버킷팅. CCS 루프는 청도·부산을 두 번 기항하므로
  같은 화물이 1번째와 9번째 기항에서 모두 적재됨.
- **수정**: 부킹별 `loadIdx`를 한 번만 배정, 양하는 그보다 뒤 기항에서만.
- **검증**: `TIGER CHENNAI 2605W` 최대 81 TEU = 귀사 BK SHEET Grand Total 81. ✅
- **교훈**: 항로는 그래프가 아니라 **순서 있는 목록**이다. 같은 노드가 재등장한다.

### 5-4. 항차 번호 재사용
- **증상**: `WAN HAI 522 W038`의 BSA가 73이어야 하는데 60으로 나옴.
- **원인**: 25년 ROB 시트와 26년 BK SHEET가 같은 `선명|항차` 키.
- **수정**: BSA 출처에 등급 부여(항차 BK SHEET 3 > 스케줄 2 > 과거 ROB 1).
- **남은 한계**: 근본 해결은 키에 연도를 넣는 것. 지금은 시즌별로 등록부를
  나누라고 매뉴얼에 명시.
- **교훈**: 업무 식별자는 대개 재사용된다. "고유해 보이는 번호"를 믿지 말 것.

### 5-5. 소스에 박힌 제어문자가 모듈 하나를 통째로 죽임 ⚠️
- **증상**: 번들 파일에서 `FXlsxWrite`가 `undefined`. 개별 파일 로드는 정상.
- **원인**: `esc()` 안에 `/[\x00-\x08…]/` 를 쓰려 했는데 파일에 **실제 제어 바이트**가
  들어감. `<script src>`로는 파싱되지만, 번들러의 텍스트 왕복을 거치면
  정규식 리터럴이 깨져 **그 모듈만 조용히 실패**.
- **수정**: 정규식을 버리고 코드포인트로 필터(`stripCtl`).
  그리고 **`build.py`가 제어문자 포함 소스를 아예 거부**하도록 방어선 추가.
- **교훈**: 가장 무서운 버그는 "한 군데만 조용히 안 되는" 버그다.
  재발 방지를 코드가 아니라 **빌드 단계**에 심어야 한다.
  (이 방어선은 실제로 나중에 내가 낸 `\x01` 오타를 즉시 잡아냈다.)

### 5-6. `\b`가 `_` 앞에서 작동하지 않음
- **증상**: 스케줄에서 읽은 항차 **전부** 서비스가 빈값. 그래서 BK SHEET 헤더
  오타가 이겨버림.
- **원인**: `\bCSC\b`는 `CSC_Schedule`에 매칭되지 **않는다**. `_`가 단어문자이므로
  `CSC`와 `_` 사이에 경계가 없다.
- **수정**: `(?:^|[^A-Z])(CSC|NWX|CCS|SKS)(?:[^A-Z]|$)`
- **교훈**: `\b`는 `[A-Za-z0-9_]` 기준이다. 업무 라벨은 `_`를 구분자로 쓴다.
  둘은 정면충돌한다.

### 5-7. 2개씩 순차 병합 → 파일 순서에 따라 결과가 달라짐
- **증상**: 파일을 정순/역순으로 넣으면 선명이 `X-PRESS PHOENIX` /
  `X-PRESS PHOEINIX` 로 갈림. 같은 배치를 반복 투입해도 1건이 계속 진동.
- **원인**: 빈칸을 낮은 신뢰도 사본이 먼저 채우면, 뒤에 온 높은 신뢰도 사본이
  **더 이상 고칠 수 없다**. 어느 쪽이 먼저 오는지가 순서에 달려 있었음.
- **수정**: 쌍 병합 폐기 → **그룹 전체를 모아 신뢰도 정렬 후 필드별 선택**.
- **검증**: 정순·역순·섞은 순서 3가지가 **레코드 지문까지 완전 동일**. ✅
  9가지 배치 조합 반복 투입에서 변경 0건. ✅
- **교훈**: "누적 병합"을 fold로 짜면 결합법칙이 깨지기 쉽다.
  전량을 모아 한 번에 정렬해 결정하면 순서 의존이 원천 제거된다.

### 5-8. 원본을 덮어써서 무한 진동
- **증상**: 같은 파일을 계속 넣는데 매번 "1건 변경". `svc1: NWX→CCS→NWX→…`
- **원인**: 스케줄 기준으로 `svc1`을 **덮어썼음**. 다음 업로드에서 원본이
  다시 `CCS`를 주장 → 또 보정 → 영원히 반복.
- **수정**: `svc1`은 원본 그대로 두고 `svcEff`(파생)에 보정값. 집계는 `svcEff` 사용.
- **교훈**: 멱등성(idempotence)을 지키려면 **읽은 값과 계산한 값을 섞지 말 것.**
  "덮어쓰기"는 언제나 진동의 씨앗이다.

### 5-9. `FULL`을 자리표시자로 인식하지 못함
- **증상**: 부킹 3건 7 TEU가 사라짐.
- **원인**: B/L 자리에 `FULL`이 8번 쓰이는데 자리표시자 목록에 없어서,
  서로 다른 부킹 3건이 하나의 키로 뭉개짐.
- **수정**: 자리표시자 집합 확장(`MT` `FULL` `T.B.N` `TBA` `N/A` `PENDING` …)
  + 등장 순번을 키에 포함.
- **교훈**: 업무 파일의 "빈칸"은 진짜 빈칸이 아니라 **관용어**다.
  실데이터에서 짧고 반복되는 값을 세어보면 금방 드러난다.

### 5-9b. 파일 갱신 경로에서 자리표시자 B/L이 또 뭉개짐
- **증상**: 1회차는 정상. 갱신된 파일에 같은 학습을 또 넣으면 `Empty Repo` 3건이
  첫 번째 `Empty Repo` 행으로 몰려 값이 뒤섞임.
- **원인**: `propagate`의 매칭 키를 **정규화한 B/L 하나로만** 잡았음. 1회차에는
  대상 파일에 그 행들이 없어서(전부 신규) 문제가 드러나지 않았다.
- **수정**: 자리표시자 B/L은 `선명|항차 + POL>F.POD + 비고문` 복합 키로 매칭하고,
  **대상 행을 한 번씩만 소비**(같은 키가 여러 행이면 순서대로 1:1 배정).
  수량은 키에서 제외 — 수량 변경이 바로 갱신의 목적이므로.
- **교훈**: 같은 함정(§5-9)이 **다른 코드 경로에 그대로 재발**했다. 한 곳을
  고쳤다고 끝이 아니다. "이 식별 문제를 여기서도 풀어야 하나?"를 매번 물어야 한다.

### 5-9c. workbook.xml 수정이 저장되지 않음
- **증상**: `_FilterDatabase` 정의 이름이 `$B$7:$AC$375`에서 그대로. 자동 필터
  범위만 늘어나고 정의 이름은 안 늘어남.
- **원인**: `open()`에서 `workbook.xml`을 `pkg.wbDoc`에 따로 파싱해두고,
  `save()`는 `pkg.docs[경로]`만 순회했다. **같은 문서를 두 곳에서 다르게 들고 있었음.**
- **수정**: `docs['xl/workbook.xml'] = wbDoc` 으로 한 객체를 공유.
- **교훈**: 같은 자원을 두 이름으로 들고 있으면 한쪽 수정이 조용히 사라진다.

### 5-11. 버튼이 하나도 안 눌리고 있었음 ⚠️⚠️
- **증상**: 탭 전환, 정렬, 실행 버튼이 **전부** 무반응. 콘솔 오류도 없음.
- **원인**: `wire()` 안에서 `$('#btnLoadProj').addEventListener(...)` — 그런 id가
  index.html에 없어서 `null.addEventListener`로 TypeError. `wire()`가 거기서
  중단되고, **그 뒤에 등록되는 `document.addEventListener('click', ...)`가
  아예 붙지 않았다.** 화면은 정상적으로 그려지므로 겉으로는 멀쩡해 보였다.
- **왜 오래 못 찾았나**: 검증할 때 `FApp.tab = 'x'; FApp.rebuild()`로 탭을
  **우회 전환**했다. 사람이 실제로 클릭하는 경로를 한 번도 밟지 않았다.
- **수정**: `on(sel, ev, fn)` 헬퍼 — 요소가 없으면 그 하나만 건너뛰고
  `console.warn`. 그리고 **실제 `.click()`으로 전 탭·버튼·정렬·필터를 순회하는
  검증 단계를 추가**.
- **교훈**:
  > 렌더링 검증은 상호작용 검증이 아니다. `innerHTML.length > 0`은
  > "버튼이 눌린다"를 전혀 보장하지 않는다.
  >
  > 그리고 초기화 코드에서 한 줄의 실패가 **뒤에 오는 전부**를 죽이지 않게 하라.

### 5-10. PowerShell 5.1이 스크립트를 ANSI로 읽음
- **증상**: `바탕 화면` 경로가 `諛뷀깢 ?붾㈃`로 깨져 파일을 못 찾음.
- **수정**: 스크립트에 비ASCII 리터럴을 두지 않고
  `[Environment]::GetFolderPath('Desktop')`로 경로를 구성.
- **교훈**: Windows 한국어 환경 + PS 5.1에서는 **스크립트 파일에 한글을 박지 말 것.**
